# 撮影用デモデータ シード（開発用ツール）

公式サイトのヘルプページ用スクリーンショットを wp-env の実画面から再現性のある形で撮るための
デモデータ投入スクリプト。**プラグインの出荷コードには一切含まれない**（`tests/` は `.distignore`
で ZIP から除外される）。DB スキーマは変更しない（データ投入のみ。`dbDelta` / `smart_booking_db_version`
には触れない）。

## 使い方

```bash
# 投入（何度実行しても同じ状態に収束する）
npx wp-env run cli wp eval-file wp-content/plugins/smart-booking/tests/screenshots/seed/screenshot-seed.php

# 撤去（このスクリプトが作った行だけを削除し、変更したオプションを元に戻す）
npx wp-env run cli wp eval-file wp-content/plugins/smart-booking/tests/screenshots/seed/screenshot-purge.php
```

## 撮影の前提: 管理画面ロケールは `ja`

既存のマニュアル画像 27 枚は **日本語 UI**（サイドバー「ダッシュボード / 投稿 / …」、右上「こんにちは、admin さん」）
で撮られている。英語 UI のまま撮ると寸法が一致していても並べられないため、**シードが管理画面ロケールを
`ja` に切り替える**。

- 言語パック `ja` が未導入なら自動でダウンロードする（導入済みなら再ダウンロードしない＝冪等）。
- サイト既定ロケール option `WPLANG` を `ja` にする。
- 管理者ユーザーの `locale` user_meta が「サイト既定以外」だと `WPLANG` が効かないため、
  変更前の値を退避したうえで空（サイト既定）にする。

**purge すると元のロケールへ完全に戻る**（`WPLANG` が元から未設定なら option ごと削除＝英語に戻り、
user_meta も変更前の値へ復元される）。

> なぜ戻せる形にするか: 回帰スイート `npx playwright test` は wp-env のグローバル状態を共有する。
> ロケールを `ja` に固定したまま放置すると回帰スイートの前提を恒久的に変えてしまうため、
> **「撮影セッションの間だけ ja、purge したら元通り」** にしてグローバル状態の変更を撮影運用に封じ込める。

言語パックの取得は外部通信（api.wordpress.org）を伴うが、これは**開発用シードスクリプト内の処理**であり
出荷コード（`includes/` `src/`）の通信ではない。オフライン等でダウンロードに失敗した場合は
**ロケールを一切変更せず**（＝退避もしない）警告を 1 行出して、他のデータ投入は続行する。
その場合は下記を実行してから再度シードすること。

```bash
npx wp-env run cli wp language core install ja
```

## 冪等性の仕組み

- 作成した行の id はすべてレジストリ option **`smart_booking_screenshot_seed`** に記録する。
- 2 回目以降は「レジストリに載っている id の行だけ」を対象に処理する。`TRUNCATE` は使わない。
  `DELETE` の `WHERE` は必ずレジストリ由来の `id IN (...)` に限定する。
- **id を保つ対象（UPDATE）**: 店舗 / 担当者 / フォーム / カスタムフィールド。
  管理画面に出るショートコード `[smart_booking form_id="N"]` の `N` が実行ごとに変わると
  撮影済みスクリーンショットと食い違うため。
- **作り直す対象（DELETE → INSERT）**: スケジュール / 予約（「今日からの相対日付」で作るため）。
  削除順序は 予約メタ → 予約 → スケジュール（参照切れ＝孤児を作らない）。
- ユーザーの既存データ（レジストリ外の行）は読むだけで変更しない。同じ
  (店舗, 担当者, 日付, 開始時刻) にレジストリ外の枠が既にある場合は作成をスキップする。
  レジストリ外の予約から参照されているスケジュールは削除せず保護する。

## デモ店舗・デモ担当者の並び順（sort_order）

管理画面の店舗／担当者一覧は `sort_order ASC, id ASC` 順（`includes/rest/class-rest-stores.php` /
`class-rest-staff.php` の `get_items()`）。wp-env には回帰スイートのフィクスチャである
`店舗1` / `担当者1`（どちらも id=2・`sort_order=10`）が存在し、そのままだと住所も電話も空の
カードがマニュアル画像の先頭に写り込む。

このフィクスチャは **削除できない**。`tests/e2e/phase3-helpers.js` の `restoreBaseline()` が
基線として明示的に再 INSERT しており、`tests/e2e/bug-a-plain-regate.spec.js` /
`phase2-reservations-smoke.spec.js` / `phase3-flow.spec.js` が `store_id: 2` に依存している
（消すと回帰が壊れる）。

そこで**デモ側の sort_order をフィクスチャ（10）より小さい固定値にして上に並べる**。

| 行 | sort_order |
|---|---|
| `デフォルト`（is_system=1・シード対象外・一覧非表示） | 0 |
| `渋谷店` / `新宿店` / `横浜店`（デモ） | 1 / 2 / 3 |
| `山田 太郎` / `佐藤 花子` / `鈴木 一郎` / `田中 次郎`（デモ） | 1 / 2 / 3 / 4 |
| `店舗1` / `担当者1`（回帰フィクスチャ・**変更しない**） | 10 |

- フィクスチャの行は **1 バイトも触らない**（DELETE も UPDATE もしない）。purge すればデモ行が
  消えて元の並びに完全復帰する。
- `0` は使わない。システムエンティティ `デフォルト` が 0 であり、「デフォルト = sort_order 最小」
  という前提（v0.5.2）を崩さないため。負値も同じ理由で使わない。
- 固定値なので 2 回目以降の実行でも値が動かない（冪等）。
- 併せてフロント予約フォームの店舗／担当者の並びもデモ 3 店舗が上に来る。撮影上は望ましい挙動。
- ユーザーの既存店舗が 1〜3 を使っている環境では同値になり `id ASC` で順序が決まる
  （デモが後ろに回る）。撮影は wp-env のクリーン環境で行う前提のため許容する。
  ユーザー行を書き換えて回避することはしない（非破壊の原則）。

## 投入されるデータ（撮影 spec が依存してよい「確定した名前」）

| 種別 | 名前 |
|---|---|
| 店舗 | `渋谷店` / `新宿店` / `横浜店`（表示順もこの通り。sort_order = 1 / 2 / 3） |
| 担当者 | `山田 太郎`（渋谷店） / `佐藤 花子`（渋谷店） / `鈴木 一郎`（新宿店） / `田中 次郎`（横浜店）。sort_order = 1 / 2 / 3 / 4 |
| フォーム | `初回相談フォーム` / `オンライン相談フォーム`（既存のデフォルトフォームは未変更） |
| 初回相談フォームの項目 | `氏名` / `メールアドレス` / `電話番号` / `ご相談内容`(textarea) / `ご相談の種別`(radio: 初めて・2回目以降) / `ご住所`(address) / `初回相談で気になる点`(textarea・条件フィールド: ご相談の種別＝初めて) |
| オンライン相談フォームの項目 | `氏名` / `メールアドレス` / `電話番号` / `ご希望のオンラインツール`(select: Zoom・Google Meet) |
| 予約者名 | `高橋 健太` / `渡辺 さくら` / `中村 大輔` / `小林 みなみ` / `加藤 隆` / `吉田 あかり` / `山口 拓也` |

- スケジュール: 今日から 21 日間の平日、1 日 4 枠（10:00 / 11:00 / 14:00 / 15:00・定員 6）。
  1 日の 4 枠に **空きあり×2 / 残りわずか×1 / 満席×1** が必ず混在する。
- 予約: 7 件（`pending` 承認待ち×2 / `approved` 承認済み×3 / `cancelled` キャンセル×2）。
  メールは全て `@example.com`、電話は `090-0000-0001` 〜 の連番（実在しない値）。
- 変更する option: `smart_booking_show_store_front=1` / `smart_booking_show_staff_front=1` / `WPLANG=ja`
  （いずれも変更前の値をレジストリの `options` 区画に `{ existed, value }` で退避し、purge で完全に元へ戻す）。
- 変更する user_meta: 管理者の `locale`（サイト既定以外なら空にする。変更前の値はレジストリの
  `user_locales` 区画に退避し、purge で復元する）。
- シード実行時のサマリ末尾に `--- 管理画面ロケール ---` の 1 行が出る
  （例: `WPLANG = 未設定(en_US) → ja  (言語パック ja: 導入済み（再ダウンロードなし） / ユーザー個別ロケール: 変更なし（サイト既定のまま）)`）。

**id は環境によって変わる**（AUTO_INCREMENT の状態に依存する）。撮影 spec は id をハードコードせず、
名前で引くか、レジストリ option `smart_booking_screenshot_seed` から読むこと。シード実行時の
サマリ出力にも店舗 id / フォーム id とショートコードを表示する。

## 注意

- レジストリ option `smart_booking_screenshot_seed` は `smart_booking_` 接頭辞を持つが、
  `uninstall.php` の明示リストには（出荷コードなので）含まれていない。
  そのため **`tests/e2e/phase1-uninstall.spec.js`（U-2: `smart_booking\_%` の option が 0 件）を
  実行する前には必ず purge を実行すること。**
- 予約は DB へ直接 INSERT する。`smart_booking_reservation_received` フックは発火させないため、
  シード実行でメール送信・外部連携は起きない。
- **撮影が終わったら purge する。** 管理画面ロケール `ja` を残したまま回帰スイートを回さないこと
  （`tests/e2e/` は WP コア管理画面の英語文字列に依存していないため実害は確認されていないが、
  グローバル状態を撮影セッションの外へ持ち出さないという運用を守る）。
- ダウンロード済みの言語パック本体（`wp-content/languages/ja*.mo`）は purge でも削除しない。
  ロケールは `WPLANG` の復元で元に戻るため表示は英語へ戻り、次回シードは再ダウンロード不要になる。
