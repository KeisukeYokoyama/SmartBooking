### 実測の根拠（修正前・`getComputedStyle` 実測）

| 対象 | `background-image` | `background-repeat` | `background-position` | 症状 |
|---|---|---|---|---|
| `select:disabled`（保護フィールドの種別・表示条件の親の種別） | WP コアの矢印 SVG | **`repeat`** | **`0% 0%`** | **矢印がタイル状に並ぶ** |
| `.smb-field.has-error .smb-select` | **`none`** | `repeat` | `0% 0%` | **矢印が消える** |
| `select`（通常状態） | WP コアの矢印 SVG | `no-repeat` | `calc(100% - 8px) 55%` | 正常 |

カスケードの内訳と特異度の計算は `docs/bugs/admin-disabled-select-arrow-tiling.md` を参照。
要点は「`background: <色>` は image だけでなく **repeat / position / size も initial へ戻す**」こと。

## 2. 全件確認（同じショートハンドで image を潰している箇所は他に無いか）

**静的（grep）**: `background:` ショートハンドは `src/admin/admin.scss` に 172 件、
`src/frontend/styles/frontend.css` に 89 件。うち **background-image を持ちうる要素に当たるもの**を
selector 単位で突き合わせた結果:

| 箇所 | 判定 |
|---|---|
| `admin.scss` `.smb-input, .smb-textarea, .smb-select`（基底 / `:disabled` / `.has-error`）3 行 | ❌ **是正対象**（WP コアがセレクトに矢印画像を与えるため） |
| `admin.scss:836` `.smb-card__placeholder { background: linear-gradient(...) }` | ✅ 問題なし。画像は**自前**で、後から潰すルールが存在しない。`repeat` だが `background-size` 未指定の linear-gradient はボックス全体を覆うため見た目は不変 |
| `frontend.css` `.smb-front-form__select` / `.smb-front-select` の矢印（linear-gradient 2枚） | ✅ 問題なし。共有ルールの `background:` ショートハンドは**矢印ルールより前**にあり、同特異度で**後勝ち**になる。`.has-error` は既に `background-color:` を使っている |
| フロントのその他 `:disabled`（`.smb-front-day-tile` / `.smb-front-time-btn` など） | ✅ 問題なし。いずれも画像を持たないボタン |
| 管理画面のチェックボックス（`.smb-switch input[type='checkbox']`） | ✅ 問題なし。`opacity: 0` の視覚的非表示で、見た目は自前の `__track` / `__thumb` が描く |

**動的（ブラウザ実測スイープ）**: ログイン後、管理画面5ページ ＋ 設定4タブ ＋ フィールド編集モーダル
＋ フロント予約ページで**全要素**を走査し、「`background-image != none` かつ `background-repeat` が
`repeat`」を抽出。検出されたのは上表の2件（`select:disabled` と `.smb-card__placeholder`）のみで、
**フロントは0件**。さらに `.smb-field.has-error` を DOM に注入してセレクトの計算値を取り、
矢印が消えることを確認した（＝ B の検出はこの動的スイープによる）。

## 3. E2E を追加するか → **追加しない**（判断と根拠）

- 変更は**塗りだけ**で、DOM・イベント・状態遷移・REST に一切触れない。回帰スイートは
  **計算スタイルのうち `backgroundColor` しか assert していない**（`phase9-redesign-style` /
  `regression-gen-a-visual` / `card-unification-visual` / `few-left-visual-repro` /
  `phase9-redesign-confirm-responsive` の5本。いずれもフロント側で、今回触らない）。
  `background: var(--x)` → `background-color: var(--x)` は **計算後の `backgroundColor` が同値**なので、
  これらの assert は挙動が変わらない。
- 「矢印が1個か複数か」を守るためだけに `background-repeat` を assert するテストを足すと、
  **WordPress コアの CSS に依存した assert** になる（矢印画像も位置もコア側の実装詳細）。
  コアの更新で壊れる脆いテストになり、回帰スイートの信頼性をむしろ下げる。
- 代わりに **再発防止は 2 つの仕組みで担保**する:
  1. `admin.scss` の当該ブロックに**理由つきのコメント**を置き、ショートハンドを使わない約束を明文化。
  2. 起票 `docs/bugs/admin-disabled-select-arrow-tiling.md` に**計算値での検証手順**を残す
     （`background-repeat: no-repeat` / `position: right 8px top 55%` の実測）。

## 4. 回帰ゲート（絞り込みの根拠）

CSS のみの変更なので、**変更が触る範囲＝「計算スタイルを assert する spec」＋「変更対象の要素を
実際に操作する管理画面 spec」＋「バンドル再生成のサニティ」** に絞って `git stash` 比較を行う。

| spec | 選定理由 |
|---|---|
| `phase9-redesign-style.spec.js` | 計算スタイル（`backgroundColor`）を直接 assert する |
| `regression-gen-a-visual.spec.js` | 同上 |
| `card-unification-visual.spec.js` | 同上（`rgb(255,255,255)` を assert） |
| `phase2-form-settings.spec.js` | 変更対象の `.smb-input` / `.smb-select` を最も多く操作する管理画面 spec |
| `v030-conditional-admin.spec.js` | 表示条件のセレクト（`has-error` 状態にも到達しうる） |
| `v054-condition-parent-guard.spec.js` | **まさに `disabled` なセレクトを検証する spec**（今回の修正対象そのもの） |
| `v030-address-field.spec.js` | 種別セレクトの切替 ＋ フロントの住所欄 |
| `phase3-flow.spec.js` | フロント予約フローの通し（`npm run build` 再生成のサニティ） |

除外した spec 群の根拠: 今回の差分は `.smb-input` / `.smb-textarea` / `.smb-select` の
**塗りの指定方法のみ**で、これらを含まない画面（スケジュールのカレンダー、予約一覧の表、
メール送信経路、アンインストール）には到達経路が無い。`phase1-uninstall` は破壊的スイートで、
実行すると基線フィクスチャが戻らない既知の負債（`docs/bugs/phase1-uninstall-no-fixture-restore.md`）が
あるため、CSS 変更の判定には用いない。

**判定結果は `docs/handoff/state.md` の v0.5.6 節に記録する。**
