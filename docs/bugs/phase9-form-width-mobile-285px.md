# ✅ クローズ: phase9「フォーム幅 450px 以下」テストが mobile で失敗（実測 285px）

最終更新: 2026-09-12（**クローズ**）
起票元: v0.5.3（バリデーション表示・maxLength・カラム順・手動予約必須）の回帰確認中に検出。
重大度: 🔵 低（見た目のレイアウト検証。予約・保存の機能挙動には無関係）。
**結論: 実装（285px）が正。テストが「実装されたことのない仕様」を固定していた。テスト側を構造的な性質へ書き換えて解決。**

## 事象（当時）

`tests/e2e/phase9-redesign-flow.spec.js` の
**「main 画面のフォーム幅が 450px 以下に制限されている (desktop)」** が
**[mobile] プロジェクト（viewport 375px）で失敗**した。desktop（1280px）では成功。

```
expect( width ).toBeGreaterThanOrEqual( expected - 4 );
Expected: >= 323
Received:    285
```

テストは mobile（375px）で `.smb-front-main-page` の幅が `calc(100vw - 48px) ≒ 327px`（許容 323〜331px）になることを期待していたが、**実測は 285px**。

## 回帰ではない（証跡）

- v0.5.3 の全変更を `git stash` で退避した**素のコード（v0.5.2 公開版相当）でも同一テストが同じく失敗**することを確認済み（baseline 差分・2026-08-17）。→ **プリエグジスティングな失敗**。
- v0.5.3 の変更は **CSS・幅指定を一切触っていない**。desktop 側は成功しており、mobile のみの既存の乖離。

## 根本原因（2026-09-12 の調査で確定）

判断材料の整理は `docs/investigation/front-main-page-width-375px-20260912.md`（**調査のみ・コード無変更**）。要点:

- **285px は計算どおり**。`375 −（テーマのグローバルパディング 30+30）−（`.smb-front-root` の 15+15）`。想定外の余白は無い。
- 期待値 `100vw − 48px` の出典は `docs/legacy-ui-handover/spec-amendment-frontend-redesign.md:113-114`（**アーカイブされた申し送り文書**。現行の凍結正本 `docs/smart-booking-spec.md` に幅の記述は無い）。
- **`calc(100vw - 48px)` は CSS 宣言として一度も実装されていない**（`src/` 内の 2 ヒットはどちらもコメント）。実装（Gen-A）は同じ要求を `width: 100%`（＝器いっぱい）と読み替えており、`frontend.css:2767`（Gen-D）のコメントが「**既存の** `width: calc(100vw - 48px)`」と**誤記**したまま語り継がれ、テストの期待値に流れ込んだ。
- ＝ **バグではなく、存在しなかった仕様に対してテストが書かれていた。**
- テーマのグローバルパディングは Twenty Twenty-Five で `clamp(30px, 5vw, 50px)`＝**ビューポートとテーマで変わる**。**ビューポート相対の絶対値を期待値にすること自体が誤り**（テーマ非依存に書けない）。

## 判断（2026-09-12・人間決定）

**案A を採用。テストの期待式を構造的な性質へ書き換える。出荷コード（CSS）は無変更。**

選択肢の比較は調査レポート §5 が正本。案B（プラグイン側の余白を詰める）は **327px に届かないうえ全ユーザーの表示が動く**、案C（テーマ余白の打ち消し）は**テーマと戦うためリスク最大**、案D（現状維持）は**赤が残り続ける**ため、いずれも採らない。

## 対応（2026-09-12・実施済み）

**テストのみの変更。出荷コード（PHP / JS / CSS / REST / DB）は 1 行も触っていない ＝ 配布物・ユーザーの表示は不変。**

### 新しい期待式（構造的な性質）

実装は `.smb-front-main-page { max-width: 450px; width: 100% }` ＝ **「器の幅いっぱい、ただし最大 450px」**。
この設計そのものを検証する形に置き換えた（`el.parentElement` の content box 幅を実測して基準にする）。

| # | 期待する性質 | 根拠 |
|---|---|---|
| (a) | `width === min( 450, 器の content box 幅 )`（±1px） | `max-width: 450px` + `width: 100%` の定義そのもの。テーマ余白が何 px でも成立する |
| (b) | `width <= 452`（±2px 許容） | 仕様「フォーム最大幅 450px」。現行正本にも残る唯一の幅要件 |
| (c) | ビューポートからはみ出さない（`left >= -1` / `right <= innerWidth + 1`）かつ `documentElement.scrollWidth <= innerWidth + 1` | 「横スクロールを作らない」はテーマ非依存に成立すべき性質 |
| (d) | 器が 450px 以上なら `width >= 448`／450px 未満なら `width >= viewport × 0.5` | 前者は max-width の支配を確認。後者はレイアウト崩壊（器が潰れる）だけを捕捉する緩い下限（375px の実測 285px = 76%）。**絶対値を固定しない** |

### 変更したテスト 2 本（**同一原因。2 本目は今回の全件確認で新たに発見**）

| ファイル | 旧 | 新 |
|---|---|---|
| `tests/e2e/phase9-redesign-flow.spec.js:273` | `main 画面のフォーム幅が 450px 以下に制限されている (desktop)` / 狭い viewport で `vw − 48 ± 4` | `main 画面のフォーム幅が器いっぱい・最大 450px で、ビューポートからはみ出さない` / 上記 (a)〜(d) |
| `tests/e2e/phase9-redesign-confirm-responsive.spec.js:220` | `レスポンシブ 375px: フォーム幅 327px + 横スクロール無し` / `325 <= width <= 329` | `レスポンシブ 375px: フォームが器の幅いっぱい（最大 450px）で横スクロール無し` / 上記 (a)〜(d) + 既存の横スクロール検査 |

> ⚠️ **2 本目は起票時に見落とされていた赤**。`phase9-redesign-confirm-responsive.spec.js:220` は
> `page.setViewportSize( { width: 375 } )` で自前に 375px へ切り替えるため **desktop / mobile の両プロジェクトで赤**だった。
> さらにこの spec は `mode: 'serial'` なので、この赤が後続 2 本（×2 プロジェクト = 4 テスト）を
> **did-not-run** にしていた。v0.5.3〜v0.5.6 の回帰ゲートはいずれもこの spec を絞り込み対象に
> 含めていなかったため記録に現れていなかった。

各テストには「なぜ絶対値で検証しないのか」を調査レポートへのリンク付きでコメントとして残した（再発防止）。

### 回帰ゲート（変更が触る範囲に絞った比較・Green）

対象 2 spec × 2 プロジェクト = **26 テスト**。`tests/e2e/` 以外は無変更なので他 spec は到達不能。

| | テスト数 | expected | unexpected | skipped(did-not-run) |
|---|---|---|---|---|
| baseline（`git stash` で 2 ファイルを退避） | 26 | 19 | **3** | **4** |
| 変更後 | 26 | **26** | **0** | **0** |

- JSON レポーターを `file:project:title` で突き合わせ、**状態が変わったのは 12 件すべて説明可能**:
  - 改名 2 本 × 2 プロジェクト = 旧タイトル 4 件消滅 / 新タイトル 4 件出現（うち旧 3 件が `unexpected`、1 件が `expected`）。
  - serial abort で did-not-run だった 4 件が `skipped → expected`。
- **消えたテスト・増えたテストの実数はゼロ（26 → 26）。新規失敗ゼロ。**
- `npx wp-scripts lint-js` の指摘件数は **37 → 37**（baseline と同数。新規の lint 負債なし）。
  ※ この 2 ファイルは元から prettier 指摘 37 件を抱えている（別件の既存負債）。`--fix` は
  ファイル引数を無視して全プロジェクトを整形するため**使っていない**。
- **`npm run build` は不要**（出荷コード無変更）。Plugin Check も配布物が変わらないため再実行不要。

## 残課題（本件の派生・別途対応）

1. **`src/frontend/styles/frontend.css:2767` のコメント誤記が残っている。**
   「375px (iPhone SE 世代): **既存の** `width: calc(100vw - 48px)` で破綻しないことを担保」は事実誤認
   （当時すでに実装は `width: 100%`）。**誤記の発生源そのもの**なので直すべきだが、
   コメントでも**出荷コードの変更**になる（ビルド成果物のバイト列が変わる）ため、
   本トラック（テストのみ）では触っていない。**次に `frontend.css` を触るリリースで同時に是正する。**
   同様に `frontend.css:1651`（Gen-A）も「仕様の 450px / `calc(100vw - 48px)` を適用する」と書いて
   実際には `width: 100%` を実装しているため、読み替えた旨を 1 行追記する余地がある。
   さらに同じコメントブロックの `frontend.css:2769`「既存の `@media (max-width: 480px)` ブロック
   （**Gen-C で追加済み**）」も**帰属が誤り**（実際は `177ba69` Phase 3 Gen-D）。
   ＝ **誤記は `frontend.css:2763-2771` の 1 ブロックに固まっている**ので、まとめて直せる。
2. **`docs/legacy-ui-handover/spec-amendment-frontend-redesign.md:113-114` の扱い。**
   アーカイブ文書だが「フォームレスポンシブ幅 `calc(100vw - 48px)`」という記述は残る。
   調査レポート §7-3 の「アーカイブをまだ要件の出典として扱うのか」は**未決**。
   当面は**テスト側が現行実装を正本とする**（本件の判断）。
3. **`@media (max-width: 480px)` の `.smb-front-root { padding: 12px }` が死んでいる。**
   判断材料は調査レポート §6 + 2026-09-12 追記。**今回は削除も変更もしない（判断保留）。**
4. **別件として起票**: `docs/bugs/phase9-section-title-22px-mobile-stale.md`
   （同じ「アーカイブ文書の値をテストが viewport 非依存で固定している」系の赤）。
