# 別件（要調査）: phase9-redesign-flow「フォーム幅 450px 以下」テストが mobile で失敗（実測 285px）

最終更新: 2026-08-17
起票元: v0.5.3（バリデーション表示・maxLength・カラム順・手動予約必須）の回帰確認中に検出。
重大度: 🔵 低（見た目のレイアウト検証。予約・保存の機能挙動には無関係）。
トラック: v0.5.3 の4スコープとは独立。**本トラックではテストも CSS も変更しない（記録のみ）**。

## 事象

`tests/e2e/phase9-redesign-flow.spec.js` の

- **「main 画面のフォーム幅が 450px 以下に制限されている (desktop)」**（`:271`〜`:298` 付近）

が **[mobile] プロジェクト（viewport 375px）で失敗**する。desktop（1280px）では成功。

```
expect( width ).toBeGreaterThanOrEqual( expected - 4 );   // 293行目付近
Expected: >= 323
Received:    285
```

テストは mobile（375px）で `.smb-front-main-page` の幅が `calc(100vw - 48px) ≒ 327px`（許容 323〜331px）になることを期待するが、**実測は 285px**。

## 回帰ではない（証跡）

- v0.5.3 の全変更を `git stash` で退避した**素のコード（v0.5.2 公開版相当）でも同一テストが同じく失敗**することを確認済み（baseline 差分・2026-08-17）。→ **プリエグジスティングな失敗**。
- v0.5.3 の変更は **CSS・幅指定を一切触っていない**（フロントは `FormInput.jsx` のバリデーション配線と `maxLength` のみ、`frontend.css` は無改変）。desktop 側は成功しており、mobile のみの既存の乖離。

## どちらが正しいかは未確認

- **テスト期待値（≒327px = 100vw − 48px）が正**なら、CSS 側に想定外の追加パディング/マージン（実測差 ≒ 42px）がある可能性。
- **CSS（実測 285px）が正**なら、テストの期待式（`vw - 48`）がリデザイン後の実レイアウト（左右パディングやコンテナ余白の合計）を反映しておらず、テスト側の更新が必要。
- 現時点では **実機 375px で意図したフォーム幅がいくつであるべきか（仕様上の狙い）が未確認**のため、テスト／CSS のどちらを直すかは保留。

## 調査（2026-09-12 追記）

判断材料の整理を `docs/investigation/front-main-page-width-375px-20260912.md` に作成した（**調査のみ・コード無変更**）。要点:

- **285px は計算どおり**。`375 −（テーマのグローバルパディング 30+30）−（`.smb-front-root` の 15+15）`。想定外の余白は無い。
- 期待値 `100vw − 48px` の出典は `docs/legacy-ui-handover/spec-amendment-frontend-redesign.md:113-114`（**アーカイブされた申し送り文書**。現行の凍結正本 `docs/smart-booking-spec.md` に幅の記述は無い）。
- **`calc(100vw - 48px)` は CSS 宣言として一度も実装されていない**（`src/` 内の 2 ヒットはどちらもコメント）。Gen-A は同じ要求を `width: 100%`（＝器いっぱい）と読み替えて実装しており、Gen-D のコメントが「既存の `width: calc(100vw - 48px)`」と誤記したまま語り継がれていた。
- テーマのグローバルパディングは Twenty Twenty-Five で `clamp(30px, 5vw, 50px)`＝**ビューポートとテーマで変わる**。**ビューポート相対の期待値はテーマ非依存に書けない**。
- 選択肢は A: テスト期待式を構造的な性質に書き換え／B: プラグイン側の余白を詰める（**327px には届かない**）／C: テーマ余白を打ち消して全幅化（**リスク最大**）／D: 現状維持でクローズ。**所見は A**（判断は保留）。
- 付随発見: `@media (max-width:480px)` の `.smb-front-root { padding: 12px }` は後続の `@media (max-width:768px) { padding: 15px }` に打ち消されて**死んでいる**。

## 対応方針（別トラック）

1. 375px 実機で `.smb-front-main-page` の意図幅を仕様・reference-ui と突き合わせて確定する。
2. 意図幅に応じて **テスト期待式** または **CSS（`max-width`/`padding`）** の一方を修正する。
3. 修正時は desktop（450px 制限）を壊さないこと。
