# 未対応: デザインタブのフォームプレビューが「お名前」をハードコード（実装の初期値は「氏名」）

最終更新: 2026-09-12
起票元: `docs/bugs/screenshot-seed-customer-name-label.md` の全件確認で検出。
重大度: 🔵 低（表示のみ。プレビューは静的モックで、実データ・予約・保存に影響しない）。
トラック: **未着手。出荷コードの変更が必要なため、本トラック（撮影シード修正）では触っていない。**

## 事象

管理画面「フォーム設定 → デザイン」のフォームプレビューが、氏名欄のラベルを
**`お名前`** と表示する。同じ画面の下にあるフィールド一覧・実際のフロント予約フォームは
**`氏名`**（出荷コードの初期値）なので、**同一画面内で 2 つのラベルが並ぶ**。

撮影済みマニュアル画像では `design/01-design-tab.png` / `design/02-design-availability-colors.png`
の 2 枚に写る（2026-09-12 の撮影でも `screenshot-text/` の grep で検出。撮影シードの修正では消えない）。

## 原因（確定）

**出荷コードのハードコード。**

| 位置 | 内容 |
|---|---|
| `src/admin/pages/formsettings/FormPreview.jsx:58` | `お名前`（ラベル） |
| `src/admin/pages/formsettings/FormPreview.jsx:63` | `placeholder="山田 太郎"`（こちらは実装の初期値と一致している） |
| `includes/class-activator.php::seed_initial_fields_for_form()` | `field_label = '氏名'` / `placeholder = '山田 太郎'` |

`FormPreview` は docblock に「実際のフロントフォームと完全一致する必要はなく、
5 項目の色がどう反映されるかをイメージさせる簡素なサンプル」と明記された**静的モック**。
機能上の不具合ではないが、**ラベルだけ実装と違う語を使っている**のは意図ではなく取り残しと読める
（placeholder は `山田 太郎` で一致しているため）。

## 関連（同じ語の使用箇所）

- `includes/rest/class-rest-public.php:953` — バリデーションエラー文
  `「お名前を入力してください。」`。ユーザーがラベルを自由に変更できる項目なので
  「ラベルと同じ語にすべきか」は別途の判断が要る（**本件とは分けて考えること**）。

## 修正方針（案・未決）

1. **案A（推奨）: `FormPreview.jsx` のラベルを `氏名` にする。** 1 行。表示のみ。
   静的モックなので DOM 構造・イベント・REST・DB に影響しない。
2. 案B: プレビューを実データ（既定フォームの項目）から描く。
   「色の確認」という目的に対して過剰で、読み込み失敗時の扱いも増える。**非推奨。**

いずれも**出荷コードの変更＝ビルドとリリースを伴う**。次のリリースに同梱するのが妥当。
